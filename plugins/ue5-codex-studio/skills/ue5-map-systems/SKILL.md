# Map Game Systems

Read the project profile, intake bundle, and accepted requirements. Create stable `system_id` entries with player outcome, dependencies, affected profiles, implementation risks, persistent state, content needs, and acceptance evidence. Keep systemic simulation, narrative state, investigation clues, audio, localization, and tooling visible instead of collapsing everything into gameplay code.

Order work by dependency and risk. A system is not ready merely because it has a name: identify unresolved design questions and the first testable slice. Present the map for approval before writing `design/system-map.yaml`.
